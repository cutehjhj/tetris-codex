# UI 코드 검토

## 수행 절차

1. 저장소 지침과 화면 요구사항을 읽고 HTML, 스타일, 렌더링 및 이벤트 코드를 확인한다.
2. 아래 체크리스트를 정적 검토하고 가능하면 브라우저에서 확인한다.
3. 코드를 직접 수정하지 않고 결과를 보고한다.

## 점검 체크리스트

- [ ] DOM 구조: 통과 — HTML 중첩이 유효하고 id가 중복되지 않으며 필수 요소 조회가 성공한다. 실패 — 잘못된 구조나 누락된 요소 때문에 화면 또는 입력이 깨진다.
- [ ] 조작 요소: 통과 — Restart는 접근 가능한 이름을 가진 버튼이며 키보드로 조작할 수 있다. 실패 — 버튼의 의미나 이름이 없거나 키보드 조작이 불가능하다.
- [ ] 렌더링 책임: 통과 — 렌더링 함수가 전달된 상태를 표시하고 게임 규칙이나 점수를 변경하지 않는다. 실패 — 그리기 과정이 게임 상태를 변경한다.
- [ ] 반복 렌더링: 통과 — 같은 상태를 반복해서 그려도 셀·이벤트가 중복되지 않고 잔상이 없다. 실패 — DOM 또는 핸들러가 누적되거나 이전 블록이 남는다.
- [ ] 상태 일치: 통과 — 활성 블록, 고정 블록, 점수, 종료 안내가 현재 상태와 일치한다. 실패 — 표시가 누락되거나 오래된 상태를 보여준다.
- [ ] 가독성: 통과 — 이름과 함수 경계로 책임을 이해할 수 있고 규칙 상수와 중복 로직이 관리된다. 실패 — 모호한 이름, 결합된 책임 또는 중복 때문에 변경 시 오류 위험이 구체적으로 확인된다.

## 보고 규칙

코드를 직접 고치지 않는다. 체크 항목별 통과/실패와 파일·줄 또는 재현 근거를 적고, 실행하지 못한 항목은 미검증으로 표시한다.

문제는 `항목 | 심각도(높음·중간·낮음) | 개선안` 표로 보고한다. 높음은 UI 실행·핵심 조작 불가, 중간은 잘못된 표시·이벤트 중복·오류를 유발하는 가독성 문제, 낮음은 동작에 영향을 주지 않는 가독성 문제다. 문제가 없으면 그 사실과 미검증 범위를 적는다.
