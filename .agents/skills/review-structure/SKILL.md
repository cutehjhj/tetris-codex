# 구조 검토

## 수행 절차

1. 저장소 지침, PRD, README, 실제 파일 목록과 실행·테스트 설정을 읽는다.
2. 아래 체크리스트를 점검하고 문서에 명시된 실행·테스트 명령을 가능한 환경에서 수행한다.
3. 코드를 직접 수정하지 않고 결과를 보고한다.

## 점검 체크리스트

- [ ] 파일 구조: 통과 — 진입점, 게임 로직, UI, 테스트의 위치와 책임을 식별할 수 있다. 실패 — 파일이 누락되거나 배치 때문에 실행·유지보수에 문제가 생긴다.
- [ ] 역할 분리: 통과 — 핵심 게임 규칙을 DOM 없이 호출하고 테스트할 수 있다. 실패 — 규칙 계산이 DOM이나 렌더링에 의존한다.
- [ ] 의존 관계: 통과 — 모듈 참조가 유효하고 순환 의존으로 인한 초기화 문제가 없다. 실패 — 잘못된 참조 또는 순환 의존으로 실행이 깨진다.
- [ ] 실행 가능성: 통과 — README의 절차로 초기 화면과 게임을 실행할 수 있다. 실패 — 명령, 진입점 또는 필수 파일이 누락되거나 실행 오류가 발생한다.
- [ ] 테스트 가능성: 통과 — 문서화된 명령으로 핵심 로직 테스트가 실행된다. 실패 — 테스트 진입점이 없거나 필요한 실행 환경이 설명되지 않는다.

## 보고 규칙

코드를 직접 고치지 않는다. 각 체크 항목의 통과/실패와 파일·줄 또는 명령 결과의 근거를 기록한다. 실행하지 못한 검사는 미검증으로 표시하며 실패나 통과로 단정하지 않는다.

발견한 문제는 `항목 | 심각도(높음·중간·낮음) | 개선안` 표로 보고한다. 높음은 실행 불가 또는 핵심 기능 장애, 중간은 테스트·유지보수를 저해하는 구조, 낮음은 경미한 정리 문제다. 문제가 없으면 “발견한 문제 없음”과 미검증 범위를 적는다.
