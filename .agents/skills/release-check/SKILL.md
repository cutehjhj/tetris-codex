# 릴리스 점검

## 수행 절차

1. 저장소 지침, PRD, README, 정적 파일 또는 빌드 산출물 및 배포 설정을 읽는다.
2. 문서에 명시된 실행·테스트·빌드 명령을 수행하고 아래 항목을 검증한다.
3. GitHub Pages 설정은 접근 가능한 저장소 설정 또는 워크플로로 확인한다. 접근하지 못한 원격 설정과 실제 배포 동작은 미검증으로 남긴다.
4. 파일·설정 수정, 커밋·푸시 또는 배포를 직접 수행하지 않고 결과를 보고한다.

## 점검 체크리스트

- [ ] 파일 연결: 통과 — HTML의 스크립트·스타일과 모듈·이미지 참조가 실제 파일 및 대소문자와 일치한다. 실패 — 누락, 잘못된 참조 또는 대소문자 불일치가 있다.
- [ ] 하위 경로: 통과 — GitHub Pages 프로젝트 경로 아래에서 모든 필수 리소스가 정상 로드된다. 실패 — 루트 절대 경로 또는 잘못된 base 설정으로 404가 발생한다.
- [ ] 실행 안내: 통과 — README의 사전 조건과 설치·실행 명령으로 게임을 실행할 수 있다. 실패 — 필수 절차가 누락되거나 안내대로 실행되지 않는다.
- [ ] 테스트·빌드: 통과 — 문서화된 테스트가 모두 통과하고 빌드가 필요한 경우 빌드가 성공한다. 실패 — 테스트·빌드 오류 또는 명령 누락이 있다.
- [ ] 배포 산출물: 통과 — 배포 대상에 진입 HTML과 필수 자산이 있으며 별도 서버나 유료 서비스 없이 동작한다. 실패 — 개발 파일만 배포되거나 런타임 의존성이 빠진다.
- [ ] GitHub Pages 설정: 통과 — 선택한 배포 방식에 맞는 브랜치·폴더 또는 Actions 워크플로의 권한·산출물·배포 대상이 유효하다. 실패 — 배포 소스나 워크플로 설정이 실제 산출물과 맞지 않는다.
- [ ] 공개 주소 검증: 통과 — 실제 Pages 주소에서 초기 로드·새로고침·핵심 플레이·Restart가 정상이며 필수 요청 실패가 없다. 실패 — 공개 주소에서 재현 가능한 실행 오류가 있다.
- [ ] MVP 범위: 통과 — PRD F1~F12와 성공 기준 검증 결과가 있고 제외 기능에 의존하지 않는다. 실패 — 필수 기능이 미완료이거나 범위 밖 서비스가 필수다.

## 보고 규칙

코드나 설정을 직접 고치지 않는다. 항목별 통과/실패와 명령 결과·경로·설정·검증 URL을 근거로 기록하며 확인하지 못한 항목은 미검증으로 표시한다. 빌드가 없는 프로젝트는 빌드 검사를 해당 없음으로 기록한다.

문제는 `항목 | 심각도(높음·중간·낮음) | 개선안` 표로 보고한다. 높음은 공개 페이지 실행 불가·필수 기능 실패, 중간은 배포·경로 설정 또는 실행 안내 결함, 낮음은 경미한 문서 문제다. 최종 상태는 필수 검증이 모두 통과하면 준비됨, 실패가 있으면 수정 필요, 미검증이 남으면 검증 보류로 표시한다.
